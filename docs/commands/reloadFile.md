# /lmmm reloadFile

MythicMobs の Mobs / Skills / Items フォルダにある **1ファイルだけ** を、`/mm reload` をせずに読み直します。

```
/lmmm reloadFile <パス | ファイル名>
```

| 例 | 説明 |
|:---|:-----|
| `/lmmm reloadFile skills/igasoraSkills.yml` | `plugins/MythicMobs` からの相対パスで指定 |
| `/lmmm reloadFile igasoraSkills.yml` | ファイル名だけで指定(同名が複数あると候補を表示して中止) |

- 権限: `lifemoremythicmobs.command.reloadfile`(デフォルト OP)
- コンソールからも実行できます。Tab 補完でファイルを選べます。
- 最後の全体リロード以降に作った新しいファイルも、パスで指定すれば読み込めます。

## 何が更新されるか

ファイル内のスキル・Mob・アイテムを作り直し、**すでに読み込まれているものと同じオブジェクトに中身を移します**。
そのため、次のような「ロード時に相手を直接覚えている」箇所もすべて新しい定義で動きます。

- 他ファイルの `skill{s=...}`・`oT=`・`onHit` など、そのスキルを呼んでいる箇所
- Mob の `Skills` / `MetaSkills`、Mob から呼ばれるスキル
- `summon`・ドロップテーブル・Crucible アイテム(スキル・トリガー・Options・Ammo)
- **いま湧いている Mob**(スキル・トリガー・ステータスは次の発動から新しい定義)

スキルのクールダウン(`Cooldown`)は引き継がれます。

## 結果の表示

| 表示 | 意味 |
|:-----|:-----|
| 更新 / 追加 | 既存エントリを更新した数 / 新しく登録した数 |
| ファイルから消えたエントリ | ファイルから削除された名前。**全体リロードまで登録されたまま** 残ります |
| 読み込みエラー | 作り直しに失敗したエントリ(そのエントリは以前の定義のまま) |
| MythicMobs の警告 | リロード中に MythicMobs が出した警告(存在しないメカニック等) |

YAML の書式エラーがある場合は何も変更せずに中止します。
差し替えの途中で予期しないエラーが起きた場合は、その回の変更をすべて元に戻します。

## 注意点(全体リロードが必要な場面)

- **新しく追加した名前** を他ファイルから呼んでいる場合、呼び出し元のファイルもリロードしてください
  (呼び出し元は「見つからない」状態をロード時に確定しているため)。
- **湧いている Mob** の HP・装備・表示名・ボスバーなど湧いた時点で決まるものは、湧き直すまで変わりません。
- **プレイヤーが持っているアイテム** の名前・Lore・エンチャント等は変わりません(スキルやトリガーは新しい定義で動きます)。
- 行ごとの `cd=` など、メカニック単位のクールダウンはリセットされます。
- `Template` で他ファイルの Mob / アイテムを親にしている場合、親を更新しても子は更新されません。
- MythicMobs / MythicCrucible の内部構造に依存しています。MythicMobs 5.12.1 / Crucible 5.12.1 で確認済み。
  バージョンを上げた場合は、まずテストサーバーで動作を確認してください。
